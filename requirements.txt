# py61850. Two things now, where it used to be one. It is still the GLV's MMS
# transport (`MmsClient`, `decode_data_definition`, `py61850.mms.pdu`), and
# since 0.3.0 it is also the IEC 61850-6 reader: `py61850.scl` builds the
# document, the type templates and the per-IED model that four tools here read
# an SCD through. SELlib 3.0.0 deleted its own copy of that reader and depends
# on this one, so pip would install it either way -- naming it here is what
# says pac-ct calls it directly and would notice it going away.
#
# `>=0.3.0`, a FINAL. Until 2026-09-08 this file pinned `>=0.2.0.dev1` and had
# to: PyPI carried no 0.2.0, and PEP 440 sorts a `.devN` BEFORE its release, so
# a plain `>=0.2.0` matched nothing, pip failed, `app.py` exited and not one of
# the nine tools came up. Naming a pre-release in the specifier is also what
# lets pip take one without `--pre` on the command line.
#
# That is over, and the pin must not name a pre-release again while a final
# exists: a specifier that mentions one tells the resolver pre-releases are
# eligible FOR THAT REQUIREMENT, so `>=0.3.0.dev2` would keep letting a future
# `0.4.0.dev1` in silently on a fresh install.
#
# A normal boot deliberately does NOT update: `app.py` calls pip only when a
# package fails to import, and a substation usually has no internet -- a
# `pip install -U` on every `--web` would turn "no network" into "not one of
# the nine tools comes up" (app.py exits on pip's error). To update on
# purpose: `python3 app.py --atualizar-deps`.
# `>=0.4.0,<0.5`, and BOTH halves were moved on purpose on 2026-09-11.
#
# The old pin was `>=0.3.0,<0.4`, and that ceiling was insurance against a real
# defect: 0.4.0 makes the SCL parser keep XML comments, and `strip_ns` then
# receives a comment node's `tag`, which is a FUNCTION and not a string -- so
# `iter_local` and `children_local`, which call it on every node they walk,
# raised `AttributeError: 'function' object has no attribute 'rsplit'` on any
# SCD that contains a comment. Real vendor files contain comments. Unbounded,
# a CLEAN install -- or `--atualizar-deps` -- would have resolved to that
# release by itself and not one of the tools that read an SCD would have come
# up. Existing installs and the offline bundles were safe either way: they
# carry pinned wheels, and `app.py` runs pip only when an import fails.
#
# What changed is that 0.4.0 FIXED it, at the source rather than at the call
# sites: `strip_ns` now returns `""` for a tag that is not a string, and the
# guard sits in that one function precisely because every traversal in the
# package -- and every vendor library reaching the tree through it -- funnels
# there. A comment is skipped by every `== local_name` test instead of raising.
#
# So the ceiling moved for the same reason it existed, and only after the seam
# was measured. `py61850` 0.4.0 was published, then verified against the
# consumers nothing in CI checks: 931 tests here and 275 in SELlib, both with
# the released SELlib 3.0.1 -- which is the combination a clean install
# actually produces, since SELlib's own pin is an unbounded `py61850>=0.3.0`
# and will take 0.4.0 without complaint.
#
# The FLOOR moved with it, to `>=0.4.0`, so that exactly one library line is
# supported and it is the line that was tested. `>=0.3.0,<0.5` would have been
# the smaller edit and would have left 0.3.x admissible and untested.
#
# PEP 440 makes the ceiling stricter than it looks: an exclusive comparison
# refuses pre-releases OF THE VERSION IT NAMES, so `<0.5` keeps `0.5.0.dev1`
# and `0.5.0rc1` out as well -- including under `--atualizar-deps`, which
# passes `--pre`. Raise it deliberately, once the next minor has been verified
# against this suite, and never as a side effect of some other change.
py61850>=0.4.0,<0.5
