# py61850 (the GLV's MMS transport). Until 2026-08-31 this was a commit pin
# (`py61850 @ git+https://...@<sha>`), because PyPI carried only 0.0.1 and the
# client the GLV calls (`MmsClient`, `decode_data_definition`,
# `py61850.mms.pdu`) was not published anywhere. Now it is: PyPI serves
# 0.2.0.dev1, a PRE-RELEASE -- 0.2.0 final still does not exist.
#
# Naming a pre-release in the specifier itself is what lets pip install a dev
# WITHOUT `--pre` on the command line (PEP 440 / pip: pre-releases are eligible
# when the requirement mentions them). Hence `>=0.2.0.dev1` and not
# `>=0.2.0`: the latter matches no published version today.
#
# It is also what makes a NEW dev get picked up without editing this file:
#
#   python3 app.py --atualizar-deps        # pip install --pre -U -r requirements.txt
#
# A normal boot deliberately does NOT update: `app.py` calls pip only when a
# package fails to import, and a substation usually has no internet -- a
# `pip install -U` on every `--web` would turn "no network" into "not one of
# the nine tools comes up" (app.py exits on pip's error).
#
# Switch to `py61850>=0.2.0` the day the final is published.
py61850>=0.2.0.dev1
