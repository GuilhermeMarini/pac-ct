# Idea 3 — What `py61850` has, lacks, and gains

The rule from the project conventions applies throughout: **the split follows
the FILE, not the vendor.** Anything that is true of IEC 61850-6 for any vendor
belongs in `py61850`. Anything that needs a vendor's name in it belongs in
`sellib` or `siemenslib`.

Measured 2026-09-09 against `py61850` 0.3.0.

---

## 1. What exists today

`py61850/src/py61850/scl/` — **1,695 lines**, seven modules:

| Module | Bytes | Holds |
|---|---:|---|
| `model.py` | 20,059 | `Ied`, `AccessPoint`, `Server`, `LDevice`, `LogicalNode`, `DataObject`, `DataAttribute` |
| `document.py` | 12,857 | `SclDocument`, `Header`, `strip_ns`, `iter_local`, `children_local`, `privates_of`, `_declared_namespaces` |
| `templates.py` | 9,143 | `TemplatePool`, `LNodeTypeSpec`, `DoTypeSpec`, `AttributeSpec` |
| `controls.py` | 8,981 | `DataSet`, `FCDA`, `ControlBlock`, `SettingControl`, `ExtRef` |
| `communication.py` | 6,606 | `Communication`, `SubNetwork`, `ConnectedAP`, `Address`, `ControlBlockAddress` |
| `_xmlsafe.py` | 4,312 | `DtdNotAllowed`, `reject_dtd_in_file`, `reject_dtd_in_bytes` |
| `__init__.py` | 3,959 | the 30-name public surface |

**The shape is already right.** Every model class is a thin wrapper holding
`self.element = el` over a live `ElementTree` node, with `__slots__` and lazy
`el.get()` reads. `SclDocument.root` is the real ET root. This is a *view over
a live tree* — the same architecture OpenSCD uses over an `XMLDocument`, which
is why the edit layer fits rather than fights.

**Tests:** 332 test functions across 21 files. **Dependencies: none** — and
that property is load-bearing (see §5).

---

## 2. What it lacks

**Everything to do with change.** Grepped for `def write`, `def serialize`,
`def to_xml`, `def save`, `tostring`, `ElementTree.write` and `.set(` across
the package: **no matches**. The library reads SCL and cannot write it.

Concretely missing:

1. **Serialisation** — with the fidelity guarantees in `01-stack.md` §3.
2. **Edit primitives** — `Insert`, `Remove`, `SetAttributes`, `SetTextContent`,
   each computing its own inverse.
3. **A parent map** — `ElementTree` has no parent pointers, and `Remove` needs
   one.
4. **Schema-ordered insertion** — SCL content models are XSD `sequence`s, so a
   correct insertion reference must be resolved from ordering tables.
5. **Creation constraints** — whether an element *may* be created at a given
   place at all.
6. **Referential repair** — what else an edit must drag along: renaming an IED
   must follow every `ExtRef@iedName`, changing a `DataSet` must bump
   `confRev`, deleting a control block must remove its `GSE`/`SMV` address.
7. **Generators** — unique MAC addresses, APPIDs, LN instance numbers.
8. **Validation** — against the schema, and against 61850 semantics.

Items 4 to 7 are the ones the standard actually makes hard, and they are the
whole reason `scl-lib` exists.

## 3. `scl-lib` mapped onto targets

The reference library is `openscd/scl-lib` (Apache-2.0): **~85 source modules**
plus **200 NSD JSON fixtures**. This maps what each area corresponds to here.
Nothing is copied — see `01-stack.md` §5. The column says where the *capability*
lands.

### To `py61850` — the standard, for any vendor

| `scl-lib` area | Modules | Capability |
|---|---:|---|
| `tBaseElement` | 7 | `identity`, `getReference`, `parentTags`, `tags`, `isPublic` — **the schema-ordering tables**, and the canonical identity of any SCL element |
| `tExtRef` | 8 | `subscribe`, `unsubscribe`, `isSubscribed`, `doesFcdaMeetExtRefRestrictions`, `matchDataAttributes`, `matchSrcAttributes`, `sourceControlBlock` |
| `tControl` | 8 | `updateConfRev`, `updateDatSet`, `findControlSubscription`, `removeControlBlock`, `controlBlockObjRef`, `pathId` |
| `tLN/supervision` | 8 | LGOS/LSVS supervision instantiation and removal |
| `tDataTypeTemplates` | 8 | `importLNodeType`, `updateLNodeType`, `removeDataType`, `insertSelectedLNodeType`, `nsdToJson` |
| `tIED` | 3 | `insertIED`, `removeIED`, `updateIED` — including the rename fan-out |
| `tDataSet` | 4 | `canAddDataSet`, `create`, `update`, `remove` |
| `tGSEControl`, `tSampledValueControl`, `tReportControl` | 10 | `canAdd*`, `create*`, `update*`, `numberReportControlInstances` |
| `tGSE`, `tSMV`, `tAddress` | 7 | `createGSE`, `changeGSEContent`, `createSMV`, `changeGseOrSmvAddress` |
| `tFCDA` | 3 | `canAddFCDA`, `fcdaBaseTypes`, `removeFCDA` |
| `tSubstation`, `tVoltageLevel`, `tBay` | 6 | `updateSubstation`, `updateVoltageLevel`, `updateBay`, `removeProcessElement`, `updateLnType` |
| `generator` | 3 | MAC address, APPID, LN instance allocation |
| `foundation` | 3 | `uniqueElementName`, NSD access |
| `tInputs`, `tServices`, `tControlWithIEDName` | 3 | `removeInputs`, `maxReportControl`, `connectedAp` |

**That is essentially all of it.** Almost nothing in `scl-lib` is
OpenSCD-specific — it is 61850-6 knowledge with a TypeScript accent, which is
the strongest possible argument that its Python equivalent belongs in
`py61850` and not in pac-ct.

Two capabilities deserve singling out because they are where the standard is
genuinely unforgiving:

- **`getReference` / `parentTags` / `tags`** — the insertion-ordering tables.
  Getting these wrong produces documents that load fine here and fail in DIGSI.
- **`updateConfRev` and the `tExtRef` restriction checks** — the rules that
  make a subscription *valid* rather than merely present.

### To the vendor libraries

| Capability | Target | Why |
|---|---|---|
| `oscd-subscriber-lb-sel`'s SEL later-binding behaviour | **`sellib`** | It needs SEL's name in it; and the `db:` sAddr grammar it would lean on is already there |
| `oscd-subscriber-lb-siemens` | **`siemenslib`** | Same test, other vendor |
| `oscd-subscriber-lb-nr` | **nowhere, for now** | NR relays are not in this project's scope |

This is the split the workspace already made, working exactly as designed: two
unrelated vendors attach to one model without either concept entering it.

### To pac-ct

Everything stateful: the document session, working documents, the journal,
undo/redo, push, the panes. `py61850` stays a library with no notion of a
session.

### Not taken

- **IEC 60870-5-104** — a different protocol; out of scope.
- **Electron file open/save, automatic backup, snapshots** — solved already by
  the project library and `derived.adopt()`.

## 4. Does anything need a new library?

**Probably not, and that is worth stating plainly** — the temptation with a
port this size is to invent packages.

| Candidate | Verdict |
|---|---|
| SLD geometry / coordinates | **`py61850`.** `sxy:` coordinates are in IEC 61850-6 itself, so a vendor-neutral library is exactly the right home |
| NSD / NSDoc data | **Data, not a library** — and constrained by IEC copyright. See `04-open-questions.md` Q1 |
| SCL XSD schemas | Same constraint, same answer |
| Undo/redo stack | **pac-ct.** Generic command-stack machinery, and it is session state |
| Edit journal | **pac-ct.** Session state by definition |

---

## 5. What this does to `py61850`'s identity

Three properties of that library are currently load-bearing, and this work
must not cost any of them.

1. **No dependencies at all.** This is why `lxml` was rejected in
   `01-stack.md` §3 despite being the easier road. The hardened-`ElementTree`
   route exists to keep this true.

2. **Its own gate.** `py61850` configures no ruff and runs no mypy; the project
   conventions record that its CI is `unittest` plus `compileall` plus
   `twine check`. New code follows that, and a default-ruleset ruff finding
   there is not a finding.

3. **It is not a support library for this project.** It is an open toolkit that
   pac-ct happens to be the first consumer of. Every capability in §3 must
   make sense to someone using `py61850` with no SEL relay anywhere — which,
   given the list is pure 61850-6, it does.

**Size estimate.** `scl-lib` is ~85 modules of TypeScript; the Python
equivalent, written idiomatically rather than transliterated, plausibly lands
between 3,000 and 5,000 lines — roughly doubling to tripling the current
`scl/` package. That is an estimate, not a measurement, and it is the largest
single number in this roadmap.

**Version consequence.** This is additive: `SclDocument` keeps reading exactly
as it does, and nothing in the 30-name public surface changes meaning. It is a
MINOR bump, not a MAJOR — but it is a large one, and the publishing order in
the project conventions applies: `py61850` before `sellib` before `pac-ct`.
